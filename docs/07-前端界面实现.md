# 07 · 前端界面实现

目标：理解 `ui/index.html` 这个单文件前端如何组织状态、渲染卡片、做缩略图编辑器，以及为什么要有 Mock 模式。

---

## 1. 一个文件，三段结构

```text
<style>   CSS 变量 + 布局 + 组件样式
<body>    静态骨架：header / main（左列表 + 右设置）/ footer / 浮层
<script>  IIFE：状态、渲染、API 调用、事件绑定、Mock
```

CSS 用变量统一主题：

```css
:root{
  --bg:#0b0d12;  --panel:#11141b;  --accent:#5b8cff;
  --ok:#35d39b;  --warn:#f0b445;  --err:#f2706b;
}
```

布局用 flex + grid：外层 `.app` 纵向三段（header / main / footer），`main` 再横切成「文件列表」和「356px 设置栏」。底部 footer 固定 58px，日志做成**向上浮层**而不是撑开文档流——早期版本把日志塞进 footer 导致底部被裁切，改成浮层后彻底解决。

## 2. API 适配层：Mock 与真实桥接

```js
let API = null;                 // pywebview api 或 mock
let MOCKED = false, adopted = false;

document.addEventListener("pywebviewready", adoptRealApi);

if (window.pywebview && window.pywebview.api) {
  adoptRealApi();
} else {
  setTimeout(() => {
    if (window.pywebview && window.pywebview.api) adoptRealApi();
    else startWithMock();
  }, 2500);
}
```

设计原因：

- 浏览器直接打开 HTML 时没有 pywebview 桥，如果什么都不做就是一片空白；
- 桥接注入的时机**晚于** DOMContentLoaded，早期写死 1.2s 超时经常误入 Mock，然后真实 API 来了却没接管；
- 现在：等到 `pywebviewready` 事件（或发现桥已就绪）就 `adoptRealApi()`；2.5 秒仍无桥才进 Mock 预览。

`adoptRealApi()` 会清掉演示数据和轮询定时器，重新 `init()`——避免「演示视频和真实视频混在一起」。

Mock API 提供了 `boot/pick_files/detect/start/poll` 等同名方法，返回假数据；`start()` 直接返回失败提示「请用 python app.py 启动」。这样界面可以在浏览器里反复调样式，不必每次都起 Python。

## 3. 卡片状态机

后端状态到前端展示的映射集中在 `STATUS_TEXT` 和 `upsertCard()`：

```js
const STATUS_TEXT = {
  pending: "待处理", detecting: "定位中", ready: "已定位",
  running: "处理中", done: "已完成", failed: "失败", skipped: "已跳过",
};
```

```js
const lowConf = f.conf > 0 && f.conf < 0.5 &&
                (f.status === "ready" || f.status === "running");
pill.className = "pill " + (lowConf ? "warn" : f.status);
pill.textContent = lowConf ? "待确认" : (STATUS_TEXT[f.status] || f.status);
```

低置信度时 pill 变黄显示「待确认」，并在水印框旁边追加 `置信度 38%` 标签。当用户忽略警告直接处理时，算法结果仍然生效——提示而非阻断，这是刻意的选择。

卡片渲染用「增量更新」：`files` 是 `path → entry` 的 Map，`renderList()` 对比后端返回的列表，新增则 `upsertCard()`，消失则移除 DOM。这样 320ms 一次轮询不会让整个列表闪烁。

## 4. 缩略图与手动改框

点击卡片缩略图打开 lightbox：

```js
function openLightbox(p) {
  const f = files.get(p);
  lbPath = p;
  $("#lbImg").src = f.thumb;
  fillLbBox(f);                 // 把 box 填进 x/y/宽/高 四个输入框
  $("#lightbox").classList.add("on");
}
```

浮层里有四个数字输入框和三个按钮：

- **应用** → `API.set_box(lbPath, [x,y,w,h])`，后端重新裁图、重新生成缩略图；
- **重新定位** → `API.detect(lbPath, corner, pad)`；
- **关闭** → 清掉 `lbPath`，隐藏浮层。

这是「算法给出建议，人做最终决定」的交互落点。对于自动定位失败的素材，这条路径比重新跑命令行快得多。

## 5. 进度与日志

```js
function startPolling() {
  if (timer) clearInterval(timer);
  timer = setInterval(poll, 320);
}
```

`poll()` 做四件事：

1. `API.poll(logIndex)` 拿增量日志和状态；
2. `renderList()` 刷新卡片；
3. `appendLogs()` 追加日志（保留靠近底部的自动滚动）；
4. 根据 `st.running / st.finished` 更新进度条文案，并在完成时处理去重提示。

进度文案把后端字段拼成人类可读句子：

```js
if (st.running) {
  text = st.current ? `${st.message} · ${st.current}` : st.message;
  if (st.eta > 0) text += ` · 预计剩余 ${fmtSec(st.eta)}`;
}
```

空闲时前端还有 1200ms 的「心跳轮询」，让界面始终跟随后端状态——比如用户在另一个入口触发了处理，或以外部方式改了文件列表。

## 6. 快捷键与导入方式

```js
document.addEventListener("keydown", async (e) => {
  if ((e.ctrlKey || e.metaKey) && e.key.toLowerCase() === "v") { /* 剪贴板导入 */ }
  if ((e.ctrlKey || e.metaKey) && e.key.toLowerCase() === "o") $("#btnAddFiles").click();
  if (e.key === "Escape") closeLightbox();
});
```

- **Ctrl+O** → 打开文件选择框；
- **Ctrl+V** → 调 `API.clipboard_files()`，把资源管理器里复制的文件路径导入；
- **Esc** → 关闭放大浮层。

关于拖放，前端只做一件事：

```js
["dragenter", "dragover", "drop"].forEach((ev) =>
  document.body.addEventListener(ev, (e) => { e.preventDefault(); e.stopPropagation(); }));
```

目的是**防止误把文件拖进窗口时浏览器直接导航到那个文件**，而不是支持导入。界面文案里也已经删除了所有「可以拖进来」的承诺，只保留「添加视频 / 文件夹 / Ctrl+V」。

## 7. 设置项如何传给后端

```js
function collectOptions() {
  return {
    mode: $("#segMode button.on").dataset.v,
    inpaint_algo: $("#selAlgo").value,
    corner: $("#selCorner").value,
    pad: parseInt($("#numPad").value, 10) || 0,
    crf: parseInt($("#rngCrf").value, 10),
    preset: "medium",
    keep_audio: $("#chkAudio").checked,
    overwrite: $("#chkOverwrite").checked,
    outdir: outmode === "custom" ? $("#inputOutdir").value.trim() : "",
  };
}
```

一个纯对象，通过 `API.start(opts)` 一次性传给 Python。后端 `_run()` 用 `opts.get(key, 默认值)` 读取，前端少传字段也不会崩——这是 JS↔Python 边界的良好实践：**宽松读取、集中收集**。
