# 09 · 复盘与扩展练习

最后一篇不引入新模块，只做两件事：把前面的知识串成一张图，然后给你几个能真正动手的扩展题目。

---

## 1. 一张图复盘

```text
输入：视频 / 目录
   │
   ├─ collect_inputs()       格式过滤 · 递归 · 去重
   │
   ├─ probe()                ffprobe JSON → VideoInfo(w,h,fps,dur,audio)
   │
   ├─ detect_watermark()
   │     ├─ 32 帧均匀抽样 → 时间中值     （抹掉运动物体）
   │     ├─ 高斯高通                     （突出笔画）
   │     ├─ 阈值 + 形态学 + 连通域       （得到候选块）
   │     ├─ 聚类 + 带验证的横向补全     （拼成一行文字）
   │     └─ 多候选打分                   （角落 × 能量 × 形态）
   │           → box + mask + confidence
   │
   ├─ 人工确认（可选）        缩略图放大 · 改 x/y/w/h
   │
   ├─ 修复引擎
   │     ├─ delogo   → FFmpeg 滤镜 → 一次编码
   │     └─ inpaint  → 逐帧 OpenCV → rawvideo 管道 → 一次编码
   │
   └─ 输出：xxx_dewm.mp4     保留音轨 · CRF 控制画质
```

界面层只是这条流水线的「遥控器」：`app.py` 的 `Api` 把每个步骤包装成 JS 可调用的方法，后台线程跑重活，前端 320ms 轮询状态。

## 2. 核心概念自测

不看文档，试着回答：

1. 为什么用**时间中值**而不是时间平均？（提示：一个路人经过时，平均值会被拉偏，中值不会。）
2. 为什么阈值取 97 分位而不是固定值？
3. `_cluster_components()` 里的能量下限 `0.45 × seed energy` 解决什么问题？
4. 为什么横向扩展后要做能量验证？没有它会怎样？
5. `_box_score()` 为什么用乘法而不是加法？
6. `delogo` 和 `inpaint` 各适合什么背景？
7. 为什么 GUI 模式下所有子进程都要 `CREATE_NO_WINDOW`？
8. 为什么 `Api.window` 要改成 `Api._window`？
9. 完成提示为什么会重复弹，怎么用序号解决？
10. 为什么当前版本不支持拖放？产品判断的依据是什么？

答案散落在 [04](./04-自动定位算法核心.md)、[05](./05-两种修复引擎.md)、[06](./06-pywebview界面后端.md)、[08](./08-启动脚本与工程化踩坑.md) 里，建议先自己想再看。

## 3. 扩展练习（按难度递增）

### 练习 A：定位结果可视化调试器 ⭐

在 `detect_watermark()` 里加一个 `debug_dir` 参数，把中间产物存盘：

- `median.png`：时间中值帧
- `highpass.png`：高通响应（归一化到 0~255）
- `binary.png`：二值化 + 形态学结果
- `candidates.png`：每个候选框用不同颜色画出来，标注 score

**收获**：能直观看到算法在哪一步出错，调参从玄学变成科学。

### 练习 B：水印模板匹配模式 ⭐⭐

对同一批模板化视频（同一平台、同一位置水印），第一次定位后把框和一小块水印图像存成模板 JSON；后续视频直接用模板框处理，跳过定位。

**提示**：新增 `--template file.json` 参数；模板里至少存 `box`、`corner`、`video_size`；分辨率不同时按比例缩放。

**收获**：理解「算法自动化」和「确定性配置」各自的适用边界。

### 练习 C：多区域水印 ⭐⭐

当前 `--box` 已支持重复传，但自动定位只会找一个框。改成自动搜索所有角落：

```python
for corner in ("br", "bl", "tr", "tl"):
    det = detect_watermark(path, corner=corner)
    if det.ok:
        boxes.append(...)
```

再增加去重（两个框重叠超过 70% 就合并）和置信度阈值。

**收获**：从「单目标检测」过渡到「多目标检测」，处理重叠框的工程质量问题。

### 练习 D：给界面加任务队列 ⭐⭐⭐

当前 `start()` 一次性把当前列表全部处理。改成：

- 支持拖拽排序卡片；
- 按顺序逐个处理，可暂停/继续；
- 暂停时等待当前文件结束再停，不留下半成品。

**提示**：在 `state` 里加 `paused`，`_run()` 每个文件开始前检查；界面加「暂停」按钮并调 `Api.toggle_pause()`。

**收获**：理解后台线程的协作式取消（不要 `Thread.kill()`）。

### 练习 E：用 FFmpeg 滤镜替代逐帧 inpaint ⭐⭐⭐

调研 FFmpeg 是否有可用的掩膜修复滤镜（如 `delogo` 的变体、外部滤镜），尝试在滤镜链里完成 inpaint，省掉 Python 逐帧管道。

**收获**：理解「滤镜链一次编码」和「外部逐帧管道」的权衡；很可能结论是「当前方案已经够好」，这也是有价值的工程判断。

### 练习 F：写一个自动测试脚本 ⭐⭐⭐

用 3~5 段已知水印坐标的短视频做基准集，写脚本自动跑：

- 定位框与标注框的 IoU > 0.7 算成功；
- 输出视频能正常解码、时长与原片一致；
- 音轨存在且时长匹配。

**收获**：把「看起来对」变成「可量化」，这是从玩具项目走向可靠工具的关键一步。

## 4. 可以迁移到其它项目的通用经验

| 经验 | 出处 |
|---|---|
| 算法失败要有确定兜底，不能让整批任务崩 | 02 的比例框 |
| 进度要区分「单任务」和「整体」，回调里换算 | 06 的 `cb()` |
| 暴露给 JS 的对象只放纯数据，原生对象藏起来 | 06 的 `_window` |
| 轮询模型要考虑幂等，否则提示会重复 | 06 的 `runSeq/toastSeq` |
| 不稳定功能宁可不做，也不要半做 | 08 的拖放取舍 |
| 中文路径用 `imencode + write_bytes` 绕开 | 08 的预览图 |
| Windows GUI 进程的子进程要 `CREATE_NO_WINDOW` | 08 的黑窗 |
| VFR 视频用 `avg_frame_rate` | 03 的 probe |
| 能复制的音轨就别重编码 | 03 的 `_audio_args()` |

## 5. 结语

这个小工具的代码量不大，但它完整走过了一遍「需求 → 算法 → 引擎 → 命令行 → 图形界面 → 打包 → 踩坑 → 文档」的闭环。真正难的不是某一行代码，而是：

- 在自动算法不可靠时，设计一套**人能介入**的机制；
- 在 Windows + WebView2 + Python + FFmpeg 这种多层技术栈里，找到**稳定可行的边界**；
- 在功能做完之后，诚实写下**它做不到什么**。

如果你把这些思路带走到别的项目里，这套教程就值了。
