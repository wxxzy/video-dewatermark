# 04 · 自动定位算法核心

这是整个项目最值得细读的一篇。目标：理解如何从一个会动、有背景、有噪声的视频里，把「静止的半透明水印框」稳定地找出来。

> 先明确：这不是 AI 模型，没有训练、没有神经网络。它靠的是**时间统计 + 空间高通 + 形态学 + 启发式打分**。优点是零依赖模型、速度可控、结果可解释；代价是对低对比度水印和复杂纹理背景无力。

---

## 1. 问题拆解

水印通常有三个可利用的特征：

| 特征 | 对应手段 |
|---|---|
| 时间上**静止**，背景人物/镜头在动 | 多帧取**时间中值**，运动的像素被抹掉 |
| 空间上是**局部窄边**（文字笔画） | 高斯**高通**，平滑背景响应低、笔画响应高 |
| 位置贴着**角落**，形状是**横向长条** | 角落先验 + 形态约束打分 |

难点在于：**背景里的亮边、桌沿、字幕往往比小号水印更"强"**。早期版本「取响应最强的连通域」就是在这里翻车的——它把背景噪点当水印。现在改成「多候选 + 综合打分」。

---

## 2. 第一步：抽帧 + 时间中值

```python
def _sample_gray(path, count=32, max_side=0):
    cap = cv2.VideoCapture(path)
    total = int(cap.get(cv2.CAP_PROP_FRAME_COUNT) or 0)
    idxs = sorted({int(x) for x in np.linspace(0, max(total - 1, 0), min(count, total))})
    ...
    g = cv2.cvtColor(f, cv2.COLOR_BGR2GRAY)
    frames.append(g)
```

- 用 `np.linspace` 在整段视频里**均匀**抽 32 帧，而不是只取开头几帧——避免开头恰好是黑场/转场；
- 转灰度，减少计算量，也符合「水印是亮度叠加」的假设；
- 可选 `max_side` 缩小，大分辨率视频能显著提速（坐标最后会按比例缩放回去）。

然后：

```python
med = np.median(np.stack(frames).astype(np.float32), axis=0)
```

`median` 是关键：假设某像素在多数帧里是背景，只在少数帧里被人挡住，那么中值就是背景值；而水印每帧都在，中值里保留下来。**运动物体被"时间抹除"，静止水印被"时间累积"。**

> 抽样帧数 `--samples` 默认 32。镜头切换特别频繁的视频可以调大，但耗时会线性上升。

---

## 3. 第二步：高通响应

```python
sigma = max(2.5, min(6.0, sh / 320.0))
hp = np.abs(med_roi - cv2.GaussianBlur(med_roi, (0, 0), sigma))
```

- `GaussianBlur` 是低通，得到「平滑版背景」；
- 原图减去低通，剩下的就是局部高频细节——文字笔画、边缘、噪点；
- `sigma` 按画面高度自适应：小图用 2.5，大图最多 6.0。水印字的笔画宽度通常就在这个尺度上。

如果整个 ROI 的 `hp.max()` 都小于 `min_contrast`（默认 8），直接判定「这里没有明显结构」，返回失败。

---

## 4. 第三步：二值化 + 形态学 + 连通域

```python
thr = max(min_contrast, float(np.percentile(hp, 97.0)))
binary = (hp >= thr).astype(np.uint8)
binary = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, np.ones((3, 3), np.uint8))
binary = cv2.morphologyEx(binary, cv2.MORPH_OPEN, np.ones((2, 2), np.uint8))
n, labels, stats, _ = cv2.connectedComponentsWithStats(binary, connectivity=8)
```

- 阈值取 **97 分位**，而不是固定值或最大值：自适应不同画质的视频；
- `CLOSE`（先膨胀后腐蚀）把断开的笔画连起来；
- `OPEN`（先腐蚀后膨胀）去掉孤立噪点；
- 连通域分析把每个笔画/图标变成候选块。

### 4.1 过滤规则

不是所有连通域都配叫「水印笔画」：

```python
if area < 5 or area > 0.30 * roi_area:      continue  # 太小/太大
if w > 0.95 * rw or h > 0.6 * rh:           continue  # 横跨整块 ROI
if w > 0.6 * rw and h < 0.03 * rh:          continue  # 贯穿式水平长边（桌沿）
if h > 0.6 * rh and w < 0.03 * rw:          continue  # 贯穿式竖直长边（墙角）
```

每个保留的块还记录一个 `energy`：

```python
energy = float(hp[y:y+h, x:x+w][sub].mean())
```

这是「这块笔画平均有多强」，后面聚类和打分都要用。

---

## 5. 第四步：把散字聚成一行

单个连通域通常只是一个字或图标的一笔。水印一般是「图标 + 几个字」排成一行，所以要把它们聚起来：

```python
def _cluster_components(seed, comps):
    bh = max(seed["h"], 6)
    e_min = 0.45 * seed["energy"]
    rest.sort(key=lambda c: abs(c["x"] + c["w"] / 2 - (x0 + x1) / 2))
    for c in rest:
        if c["energy"] < e_min:                       continue
        if not (0.45 * bh <= ch <= 2.2 * bh):         continue
        if abs((c["y"] + c["h"] / 2) - cy) > 0.7 * bh: continue
        gap = ...
        if gap > 1.4 * bh:                            continue
        cluster.append(c)
```

四个约束缺一不可：

1. **能量下限**：`0.45 × 种子能量`。同高度但弱得多的背景噪点被挡在外面——这是修 bug 时加的关键一条；
2. **高度相近**：`0.45~2.2 × 种子高度`，允许大小写差异，排除别的行；
3. **同一行**：中心 y 偏差不超过 `0.7 × 高度`；
4. **间距合理**：横向间隔不超过 `1.4 × 高度`，避免隔着一段背景把远处噪点拉进来。

排序用「到种子中心的横向距离」，由近及远并入，让聚类结果稳定。

---

## 6. 第五步：带验证的横向补全

有时字是白的，压在白衣服上，高通响应很弱，聚类会漏掉右边的几个字。所以需要横向扩展：

```python
def _grow_run(has, i0, i1, gap):
    """向两侧扩展，允许中断不超过 gap 个空位。"""
```

```python
colmax = band.max(axis=0)
ok_col = colmax >= max(thr * 0.8, 0.55 * seed_energy)
nx0, nx1 = _grow_run(ok_col, x, x + w - 1, gap=max(3, int(0.5 * hh)))
```

- 按**列**判断：只要这一列有足够强的笔画，就纳入；
- 允许中间断 `gap` 列（字间距）；
- 最多扩展 `1.3 × 原宽`，防止一路长到画面边缘。

### 6.1 能量验证：扩展的刹车

```python
base = _col_peak(hp, band0, band1, x, x + w)
if nx0 < x and _col_peak(hp, band0, band1, nx0, x) < 0.5 * base:
    nx0 = x
```

`_col_peak()` 取区间内「每列最大值的 95 分位」，代表这段区域的笔画强度。新增区域若不到原来的**一半**，就回退——这是另一处关键修复：早期版本用 `any(列 > 阈值)`，结果顺着背景纹理一路扩张，把半个画面框进去。

## 7. 第六步：多候选打分（最关键的思想）

```python
seeds = sorted(comps, key=lambda c: -c["area"] * c["energy"])[:14]
for seed in seeds:
    cluster = _cluster_components(seed, comps)
    box = ...聚类外接框...
    box = _extend_horizontally(box, hp, thr, seed["energy"], rw, rh)
    sc = _box_score(box, hp, e_norm, corner, rw, rh)
    if best is None or sc > best[0]:
        best = (sc, box, cluster, energy)
```

取能量×面积最高的 14 个块当种子，**每个都走完整流程**，最后按 `_box_score()` 打分取最优。这样即使背景某条边响应更强，只要它形状/位置不像水印，总分就压不过真正的水印。

### 7.1 打分函数

```python
def _box_score(box, hp, energy, corner, rw, rh):
    dx, dy = _corner_distance(box, corner, rw, rh)
    px = 1.0 / (1.0 + (dx / (0.10 * rw)) ** 2)
    py = 1.0 / (1.0 + (dy / (0.10 * rh)) ** 2)
    prox = px * py                       # bottom/top 模式只看 py

    aspect = w / float(h)
    h_rel = h / float(rh)
    shape = 1.0 if aspect >= 1.8 else (0.5 if aspect >= 1.2 else 0.25)
    if not (0.03 <= h_rel <= 0.30):
        shape *= 0.4

    return prox * (0.35 + 0.65 * energy) * shape
```

三项相乘：

- **角落先验 `prox`**：洛伦兹衰减，离目标角落越远分越低。`0.10 × ROI 宽/高` 是衰减尺度——水印贴边时接近 1，跑到画面中间就快速掉分；
- **对比强度 `energy`**：归一化后的笔画能量，`0.35 + 0.65 × energy` 保证弱一点也有基础分；
- **形态 `shape`**：一行文字应该宽高比 ≥1.8；高度占 ROI 的 3%~30%。像「人像块」这种宽高比接近 1 的会被压到 0.25 分。

> 相乘而不是相加，是为了让任何一项明显不合格都能把总分拉下来。之前用「取最强块」等价于只看第二项，所以经常被背景带偏。

## 8. 第七步：内边距、掩膜、坐标还原

```python
pad_x = max(2, int(round(0.03 * w)))
pad_y = max(2, int(round(0.14 * h)))
```

横向扩 3%，纵向扩 14%——纵向留得多，因为半透明水印的羽化边缘上下更容易漏。漏 1~2px 就会在成品里留一圈淡淡的水印轮廓。

掩膜来自两部分：聚类命中的连通域 + 框内高通超过阈值的像素，再做一次 3×3 膨胀，最后从小尺寸 ROI 映射回全图尺寸。这个掩膜用于预览染红和 inpaint 引擎；delogo 引擎只用外接框。

尺寸合理性最后兜底：

```python
if bwd < max(6, W * 0.01) or bhd < 4 or bwd > W * 0.8 or bhd > H * 0.45:
    return Detection(fbox, ..., ok=False, note="定位结果尺寸可疑")
```

## 9. 置信度：把不确定性交给用户

```python
confidence = min(1.0, score / 0.45)
ok = score >= 0.22
```

- `score` 是上面三项相乘的结果，理论上限约 1；
- 除以 0.45 映射到界面可读的百分比；
- 低于 0.22 判为不可信，但仍把框返回，只是 `ok=False` + 一句提示。

界面拿到 `confidence < 0.5` 会把卡片标成黄色「待确认」（见第 07 篇）；命令行则打印告警并退回保守的比例框。这比「悄悄处理出一个错的结果」负责得多。

## 10. 调试定位问题的工作流

```bash
# 1) 只看不处理，生成绿框预览
python dewatermark.py video.mp4 --dry-run --preview

# 2) 想看每个候选的分数，临时把 verbose=True
#    detect_watermark(..., verbose=True) 会打印候选 score / box / energy

# 3) 确认位置后，手动固定框
python dewatermark.py video.mp4 --box 576,1226,129,41
```

常见症状与调参方向：

| 症状 | 可能原因 | 建议 |
|---|---|---|
| 框到背景亮边上 | 背景响应更强 | 检查角落先验是否正确（`--corner`），或收紧形态约束 |
| 框偏小，漏掉后面的字 | 弱笔画被聚类能量下限排除 | 调低 `e_min` 系数（0.45）或加宽横向扩展 |
| 框过大，吞进背景 | 横向扩展能量验证太松 | 把 0.5 的验证阈值调高到 0.6~0.7 |
| 完全找不到 | 水印对比度低于 `min_contrast` | 调低 `min_contrast`，或改用 `--box` |
| 竖屏/横屏切换后失效 | ROI 比例不合适 | 调整 `CORNER_ROI` 或换 `--corner bottom` |
