# 05 · 两种修复引擎

目标：理解 `delogo` 和 `inpaint` 两条修复路径的原理、适用面和性能取舍，知道为什么默认选前者。

---

## 0. 先说清楚一件事：这不是"恢复原图"

水印是**叠加**到画面上的。原始像素被覆盖之后就丢了，任何算法都只能「根据周围像素猜一块看起来合理的内容填进去」。所以：

- 水印压在天空、纯色衣服、墙面这种**平坦区域** → 几乎无痕；
- 水印压在细密纹理、栏杆、头发丝上 → 放大看会有轻微涂抹感，这是所有去水印算法的共性。

界面里把 CRF 调小、把框贴紧水印，能减轻痕迹，但无法消除这个物理限制。

---

## 1. 统一的任务载体

```python
@dataclass
class Task:
    src: str
    dst: str
    info: VideoInfo
    boxes: List[Box] = field(default_factory=list)
    note: str = ""
```

定位阶段产出的框存进 `boxes`，两个引擎都从同一个 `Task` 出发，区别只在「怎么填这块像素」。

边界保护由 `clamp_box()` 统一负责：

```python
x = max(1, min(x, width - 3))
y = max(1, min(y, height - 3))
w = max(1, min(w, width - 1 - x))
h = max(1, min(h, height - 1 - y))
```

注意坐标从 1 开始 —— FFmpeg 的 `delogo` 滤镜需要框外至少一圈像素做插值，贴到 0 会报错。

---

## 2. 引擎一：`delogo`（默认）

```python
def build_delogo(boxes, width, height):
    parts = []
    for b in boxes:
        x, y, w, h = clamp_box(b, width, height)
        parts.append(f"delogo=x={x}:y={y}:w={w}:h={h}")
    return ",".join(parts)
```

`delogo` 是 FFmpeg 内置滤镜：对指定矩形，用**框边界上的像素做插值**，从外向内把框内填满。

```python
def process_delogo(task, crf, preset, keep_audio, on_progress=None):
    vf = build_delogo(task.boxes, task.info.width, task.info.height)
    args = ["-i", task.src, "-vf", vf,
            *_encoder_args(crf, preset, movflags),
            *_audio_args(task.info, keep_audio), task.dst]
    run_ffmpeg_with_progress(args, task.info.duration, "去水印", on_progress)
```

优点：

- **快**：纯滤镜链，一次解码一次编码，GPU/CPU 都轻松；
- **稳**：插值规则确定，不会在强边缘旁拖出奇怪色块；
- 支持多框：逗号串多个 `delogo=x=...`。

缺点：对框内复杂内容无能为力，本质就是「周边颜色渐变填充」。框越大，中间越糊。

## 3. 引擎二：`inpaint`（掩膜修复）

OpenCV 的 `cv2.inpaint()` 基于 Navier-Stokes 或 Telea 算法，把掩膜区域当作「要修补的洞」，从边界向内传播像素/梯度信息。

```python
mask = np.zeros((H, W), np.uint8)
for bx in task.boxes:
    x, y, w, h = clamp_box(bx, W, H)
    mask[y:y+h, x:x+w] = 255
flag = cv2.INPAINT_NS if algo.lower() == "ns" else cv2.INPAINT_TELEA
```

### 3.1 逐帧处理 + 管道编码

如果先把修复后的帧写成临时视频再编码，就要编码两次、磁盘 IO 翻倍。这里的做法是**把修复后的帧直接喂给 FFmpeg 的 stdin**：

```python
args = [FFMPEG, "-hide_banner", "-loglevel", "error", "-y",
        "-f", "rawvideo", "-pix_fmt", "bgr24", "-s", f"{W}x{H}", "-r", f"{fps:.6f}",
        "-i", "pipe:0"]
if keep_audio and info.has_audio:
    args += ["-i", task.src, "-map", "0:v:0", "-map", "1:a:0", *_audio_args(info, True)]
else:
    args += ["-map", "0:v:0", "-an"]
args += [*_encoder_args(crf, preset), "-movflags", "+faststart", task.dst]
proc = subprocess.Popen(args, stdin=PIPE, stderr=PIPE, creationflags=NO_WINDOW)
```

- `-f rawvideo -pix_fmt bgr24`：告诉 FFmpeg 输入是裸 BGR 帧，没有容器、没有时间戳；
- `-s WxH -r fps`：帧尺寸和帧率必须显式给，否则 FFmpeg 不知道怎么解释字节流；
- 第二个 `-i task.src` 只为取音轨，`-map` 明确「画面用管道（0:v），声音用原片（1:a）」；
- 主循环：

```python
while True:
    ok, frame = cap.read()
    if not ok:
        break
    if frame.shape[1] != W or frame.shape[0] != H:
        frame = cv2.resize(frame, (W, H), interpolation=cv2.INTER_AREA)
    fixed = cv2.inpaint(frame, mask, radius, flag)
    proc.stdin.write(fixed.tobytes())
```

帧尺寸不一致时先 resize，避免管道里字节数错位——这种错位会产生「画面撕裂」而不是直接报错，很隐蔽。

- `radius=4` 是修复半径：越大越能覆盖宽笔画，但计算量按平方增长，也更容易拖出周围颜色；
- 进度按帧数算：`idx % 4 == 0` 时回调一次，比 delogo 的时间进度粒度粗一些。

### 3.2 TELEA vs NS

| 算法 | 特点 | 适合 |
|---|---|---|
| `TELEA`（默认） | 平滑，整体自然 | 平坦背景、半透明角标 |
| `NS` | 保留结构边缘更强 | 有线条穿过的区域，但可能拖出色块 |

界面上选「掩膜修复」后会出现算法下拉框；命令行用 `--inpaint-algo telea|ns`。

## 4. 两个引擎怎么选

| 维度 | delogo | inpaint |
|---|---|---|
| 速度 | 快（一次 FFmpeg） | 慢（逐帧 OpenCV + FFmpeg） |
| 内存占用 | 低 | 中高（帧缓冲） |
| 平坦背景 | 干净 | 干净 |
| 纹理背景 | 渐变感略明显 | 有时更自然 |
| 强结构边缘旁 | 稳定 | 可能拖出色块 |
| 多水印框 | 原生支持 | 掩膜叠加支持 |

实践建议：**先用 delogo**；如果水印压在明显纹理上且放大后能看到渐变痕迹，再用 inpaint 跑同一段对比。两者都不理想时，优先考虑把框贴得更紧、或换 `--corner` / `--box` 重新定位。

---

## 5. 画质参数复盘

两个引擎最后都走 `_encoder_args()`：

```python
["-c:v", "libx264", "-crf", str(crf), "-preset", preset, "-pix_fmt", "yuv420p"]
```

- `--crf 14~16`：接近无损，文件大，适合成品；
- `--crf 18`：默认，肉眼几乎无损；
- `--crf 22~28`：体积优先，适合批量预览。

`--preset` 从 `ultrafast` 到 `veryslow`，越慢同样的 CRF 下体积越小。本项目界面固定 `medium`，命令行可自由指定。
